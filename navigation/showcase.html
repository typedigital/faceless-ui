2. Desktop Navigation (manual markup)

The same result with classic <nav><ul><li> markup — fully backwards compatible. Both variants are equivalent.

A11y notes for manual markup
  • <a href="…"> vs. <button>: Use <a> for real links (navigating to a URL) and <button> for pure toggle elements without a navigation target. <a href="#"> as a button substitute creates a confusing tab stop for screen reader users.
  • <ul><li> structure: The list structure gives screen readers context ("3 items", "item 2 of 3"). Without it, users lose their spatial orientation within the menu.
  • <nav> landmark: The <nav> element creates a landmark that screen reader users can jump straight to or skip past.
  • aria-label on the host: When a page has several navigation landmarks, each one must be uniquely named (e.g. aria-label="Main navigation"). The component logs a console warning when this attribute is missing.
  • No manual ARIA: aria-expanded, aria-controls, aria-haspopup, role, tabindex, and submenu ids are set exclusively by the component. Do not add these attributes manually.
